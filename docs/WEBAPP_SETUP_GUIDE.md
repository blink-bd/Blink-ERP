# دليل تسطيب النظام كـ Web App — خطوة بخطوة بالتفصيل الكامل

هذا الملف الوحيد اللي محتاج تتبعه من الأول للآخر عشان تشغّل النظام أونلاين، بحيث أي حد يفتحه من المتصفح (كمبيوتر أو موبايل) بلينك واحد، من غير ما يحمّل أي برنامج.

**✅ الدليل ده بالكامل بدون أي أوامر Terminal — كله زرارات وضغطات ماوس بس.** بنستخدم برنامج GitHub Desktop (واجهة رسومية) بدل أوامر Git.

**هنستخدم 4 خدمات، كلها مجانية للبداية:**

| # | الخدمة | بتعمل إيه | الرابط |
|---|---|---|---|
| 1 | **GitHub** | تخزين الكود | github.com |
| 2 | **Supabase** | قاعدة البيانات (PostgreSQL) | supabase.com |
| 3 | **Render** | تشغيل الباك إند (السيرفر) | render.com |
| 4 | **Cloudflare Pages** | تشغيل الواجهة (اللي بتفتحها في المتصفح) | dash.cloudflare.com |

⏱️ **الوقت المتوقع:** من 45 دقيقة لساعة، معظمه انتظار (الخدمات بتاخد وقت تجهّز نفسها أول مرة).

> ⚠️ Node.js وDocker اللي مثبتين على جهازك مش هيتستخدموا في النشر النهائي. هما بس للتجربة المحلية. النشر كله هيحصل على السحابة (Cloud)، جهازك بس هيستخدم لرفع الكود.

<a name="1"></a>
## 1) تجهيز حساب GitHub ورفع الكود (بدون أي أوامر Terminal)

هنستخدم برنامج اسمه **GitHub Desktop** — واجهة رسومية بسيطة (زرارات بس، بدون كتابة أي أوامر).

### 1.1 أنشئ حساب على GitHub
1. روح على **github.com**
2. اضغط **Sign up**
3. اكتب إيميلك، اختار باسورد، اختار اسم مستخدم (Username)
4. أكّد إيميلك من الرسالة اللي هتوصلك

### 1.2 ثبّت برنامج GitHub Desktop
1. روح على **desktop.github.com**
2. اضغط **Download for Windows**
3. شغّل الملف اللي نزل وسيبه يثبّت لوحده (مفيش خطوات، بيثبت تلقائي)
4. هيفتح البرنامج لوحده بعد التثبيت

### 1.3 سجّل دخول جوه البرنامج
1. في أول شاشة تفتح، اضغط **Sign in to GitHub.com**
2. هيفتحلك المتصفح، اضغط **Authorize desktop**
3. ارجع للبرنامج، هتلاقيه سجّل دخول بحسابك تلقائيًا

### 1.4 أنشئ Repository جديد من داخل البرنامج
1. من البرنامج، من قائمة **File** (فوق شمال) → **New repository...**
2. **Name**: اكتب `mobile-accessories-erp`
3. **Local Path**: اضغط **Choose...** واختار أي مكان تحب يتحفظ فيه المشروع على جهازك (مثلاً Desktop)
4. سيب باقي الخيارات زي ما هي
5. اضغط **Create repository**

البرنامج هيعمل مجلد فاضي بالاسم ده في المكان اللي اخترته.

### 1.5 حط ملفات المشروع جوه المجلد ده
1. فك ضغط ملف `mobile-accessories-erp.zip` اللي معاك
2. افتح المجلد اللي فكيت ضغطه
3. اختار **كل الملفات والمجلدات اللي جواه** (Ctrl+A)
4. اعمل **نسخ** (Ctrl+C)
5. روح للمجلد اللي عمله البرنامج في خطوة 1.4 (نفس الاسم `mobile-accessories-erp`، في المكان اللي اخترته)
6. **الصق جواه** (Ctrl+V) — لاحظ: تلصق **جوه** المجلد ده، مش تستبدله

### 1.6 ارفع الكود على GitHub
1. ارجع لبرنامج GitHub Desktop
2. هتلاقيه اكتشف كل الملفات اللي حطيتها تلقائيًا (هيظهرلك عدد كبير من الملفات في القائمة الشمال)
3. تحت في خانة **Summary** اكتب أي وصف، مثلاً: `أول نسخة من النظام`
4. اضغط **Commit to main** (الزرار الأزرق تحت)
5. فوق هتلاقي زرار **Publish repository**
6. تأكد إن اختيار **Keep this code private** مفعّل (تيك ✓)
7. اضغط **Publish repository**

### 1.7 تأكد إن الكود اتفع
1. روح على المتصفح → **github.com/USERNAME/mobile-accessories-erp** (غيّر USERNAME باسمك)
2. المفروض تشوف كل الملفات ظاهرة (docs, apps, package.json...)

✅ **خلصنا الخطوة دي — بدون أي أمر Terminal.**

<a name="2"></a>
## 2) إنشاء قاعدة البيانات على Supabase

### 2.1 أنشئ حساب وأنشئ مشروع
1. روح على **supabase.com** → **Start your project** → سجّل دخول بحساب GitHub بتاعك (أسهل حاجة، هيربطهم تلقائي)
2. اضغط **New project**
3. اختار **Organization** (لو أول مرة هيطلب تعمل واحدة، اقبل الافتراضي)
4. **Project name**: اكتب `mobile-accessories-erp`
5. **Database Password**: اضغط **Generate a password** وانسخه في مكان آمن (Notepad مثلاً) — **هتحتاجه بعد شوية ومش هيظهرلك تاني**
6. **Region**: اختار أقرب منطقة ليك (مثلاً Frankfurt لو في مصر/الشرق الأوسط)
7. اضغط **Create new project**
8. استنى دقيقة لحد ما يخلص التجهيز (هتشوف شريط تحميل)

### 2.2 فعّل الإضافات المطلوبة
1. من القائمة الجانبية اضغط **SQL Editor**
2. اضغط **New query**
3. الصق السطرين دول:
   ```sql
   create extension if not exists "uuid-ossp";
   create extension if not exists pg_trgm;
   ```
4. اضغط **Run** (أو Ctrl+Enter)
5. المفروض يظهرلك "Success. No rows returned"

### 2.3 خد رابط الاتصال (Connection String)
1. من القائمة الجانبية اضغط على أيقونة **⚙️ Project Settings**
2. اضغط **Database** من القائمة الفرعية
3. انزل لقسم **Connection string**
4. اضغط على تبويب **Session pooler** (⚠️ **مهم جدًا** — مش Transaction pooler ومش Direct connection)
5. هتلاقي رابط شكله كده:
   ```
   postgresql://postgres.xxxxxxxxxxxx:[YOUR-PASSWORD]@aws-0-eu-central-1.pooler.supabase.com:5432/postgres
   ```
6. انسخه، واستبدل `[YOUR-PASSWORD]` بالباسورد اللي حفظته في خطوة 2.1
7. احتفظ بالرابط الكامل ده في مكان آمن — **ده اللي هتحطه في Render بعد شوية**

✅ **خلصنا الخطوة دي.**

<a name="3"></a>
## 3) نشر الباك إند على Render

### 3.1 أنشئ حساب على Render
1. روح على **render.com** → **Get Started**
2. سجّل دخول بحساب GitHub بتاعك مباشرة

### 3.2 اربط الـ Repository وابدأ النشر
1. من لوحة التحكم اضغط **New +** (فوق يمين) → **Blueprint**
2. لو أول مرة، هيطلب منك **Connect GitHub account** واختار إنه يشوف الـ Repository بتاعك (أو كل الـ Repositories)
3. اختار Repository `mobile-accessories-erp`
4. Render هيلاقي ملف `render.yaml` الموجود في المشروع تلقائيًا ويعرضلك:
   - خدمة اسمها `erp-api`
5. هيطلب منك تدخل قيم بعض المتغيرات (اللي مكتوب جنبها `sync: false` في الملف):

| المتغير | القيمة اللي تحطها |
|---|---|
| `DATABASE_URL` | رابط Supabase اللي نسخته في الخطوة 2.3 |
| `FRONTEND_URL` | اكتب مؤقتًا `https://placeholder.pages.dev` (هنرجعله بعد شوية) |
| `MASTER_ADMIN_EMAIL` | إيميلك الشخصي، مثال: `you@example.com` |
| `MASTER_ADMIN_PASSWORD` | كلمة مرور قوية: **12 حرف على الأقل**، فيها حرف كبير + حرف صغير + رقم + رمز (مثال: `MyStore#2024Secure`) |

6. اضغط **Apply** في الآخر

### 3.3 استنى الـ Build
- هياخد **5 لـ10 دقايق** أول مرة (بيثبت الحزم، يعمل Build، يشغّل الـ migrations والـ seed تلقائيًا)
- تقدر تتابع اللوج (Logs) من صفحة الخدمة `erp-api` علشان تشوف إيه اللي بيحصل لحظة بلحظة

### 3.4 تأكد إنه شغّال
1. من صفحة `erp-api` هتلاقي رابط فوق شكله:
   ```
   https://erp-api-xxxx.onrender.com
   ```
2. افتحه في تبويب جديد وضيف `/api/docs` في الآخر:
   ```
   https://erp-api-xxxx.onrender.com/api/docs
   ```
3. لو ظهرتلك صفحة Swagger فيها قايمة APIs، يبقى الباك إند شغّال 🎉
4. **احتفظ برابط `erp-api-xxxx.onrender.com`** — هتحتاجه في الخطوة الجاية

> لو الصفحة ما فتحتش أو ظهر خطأ، روح لقسم [حل المشاكل](#9) في الآخر.

✅ **خلصنا الخطوة دي.**

## 4) نشر الواجهة على Cloudflare Pages

### 4.1 أنشئ حساب على Cloudflare
1. روح على **dash.cloudflare.com/sign-up**
2. سجّل بإيميلك وباسورد، وأكّد الإيميل

### 4.2 أنشئ مشروع Pages
1. من لوحة التحكم، من القائمة الجانبية اضغط **Workers & Pages**
2. اضغط **Create**
3. اختار تبويب **Pages** فوق
4. اضغط **Connect to Git**
5. اربط حساب GitHub بتاعك (هيطلب صلاحية الوصول لأول مرة)
6. اختار Repository `mobile-accessories-erp` → **Begin setup**

### 4.3 إعدادات البناء (Build settings)
املى الحقول بالظبط كده:

| الحقل | القيمة |
|---|---|
| **Project name** | `mobile-accessories-erp` (أو أي اسم تحبه) |
| **Production branch** | `main` |
| **Framework preset** | اختار `Vite` لو موجود، أو سيبه `None` |
| **Build command** | `npm install && npm run build` |
| **Build output directory** | `dist` |
| **Root directory** | اضغط **Edit** بجانبها واكتب `apps/web` |

### 4.4 متغيرات البيئة (Environment Variables)
قبل ما تضغط Deploy:
1. انزل لقسم **Environment variables (advanced)**
2. اضغط **Add variable**
3. Variable name: `VITE_API_URL`
4. Value: رابط Render بتاعك + `/api/v1` في الآخر، مثال:
   ```
   https://erp-api-xxxx.onrender.com/api/v1
   ```

### 4.5 ابدأ النشر
1. اضغط **Save and Deploy**
2. استنى دقيقة أو دقيقتين
3. هتاخد رابط شكله:
   ```
   https://mobile-accessories-erp-xxx.pages.dev
   ```

✅ **خلصنا الخطوة دي.**

<a name="5"></a>
## 5) ربط الخدمات ببعض

عندنا خطوة أخيرة مهمة: لازم نقول للباك إند (Render) يقبل طلبات من رابط Cloudflare الحقيقي (مش الـ placeholder اللي حطيناه قبل كده).

1. ارجع لـ **Render** → صفحة خدمة `erp-api`
2. من القائمة الجانبية اضغط **Environment**
3. دوّر على متغير `FRONTEND_URL` واضغط عليه للتعديل
4. غيّر قيمته لرابط Cloudflare بتاعك (من خطوة 4.5)، بدون `/` في الآخر:
   ```
   https://mobile-accessories-erp-xxx.pages.dev
   ```
5. اضغط **Save Changes**
6. Render هيعمل **إعادة تشغيل تلقائي** للخدمة (استنى دقيقة)

✅ **خلصنا الخطوة دي — النظام دلوقتي متصل بالكامل.**

<a name="6"></a>
## 6) إنشاء حساب المدير العام والتاجر الأول

### 6.1 حساب المدير العام
**اتعمل تلقائيًا** وقت الـ Build في Render، بالإيميل والباسورد اللي حطيتهم في خطوة 3.2 (`MASTER_ADMIN_EMAIL` و`MASTER_ADMIN_PASSWORD`). مش محتاج تعمل حاجة تانية.

### 6.2 سجّل دخول كمدير عام
1. افتح رابط Cloudflare بتاعك + `/admin/login`:
   ```
   https://mobile-accessories-erp-xxx.pages.dev/admin/login
   ```
2. سجّل دخول بالإيميل والباسورد بتوع `MASTER_ADMIN_EMAIL` / `MASTER_ADMIN_PASSWORD`

### 6.3 أنشئ أول تاجر (متجر حقيقي)
1. بعد الدخول، اضغط **التجّار** من القائمة العلوية
2. اضغط **إضافة تاجر جديد**
3. املى البيانات:
   - اسم النشاط التجاري
   - بريد النشاط
   - اسم مدير المتجر، بريده (اللي هيسجل بيه دخول)، كلمة مرور مؤقتة له
4. اضغط **إنشاء التاجر**
5. هيظهرلك إشعار فيه **Tenant ID** — **انسخه واحتفظ بيه**، ده اللي التاجر هيستخدمه للدخول

✅ **خلصنا الخطوة دي.**

<a name="7"></a>
## 7) تسجيل الدخول والتجربة

### 7.1 دخول التاجر
1. افتح رابط Cloudflare العادي (من غير `/admin`):
   ```
   https://mobile-accessories-erp-xxx.pages.dev
   ```
2. هيوديك لصفحة تسجيل الدخول، حط:
   - **معرّف المتجر (Tenant ID)**: من خطوة 6.3
   - **البريد الإلكتروني**: بريد مدير المتجر
   - **كلمة المرور**: الكلمة المؤقتة

### 7.2 جرّب النظام
1. روح "المنتجات" → أضف منتج بسعر تكلفة وسعر بيع
2. روح "نقطة البيع" → دوّر عليه بالاسم أو الكود → أضفه للسلة → اضغط دفع نقدي
3. روح "المخزون" أو "التقارير" → شوف إن العملية اتسجلت فعليًا

🎉 **مبروك، النظام شغّال أونلاين بالكامل.**

<a name="8"></a>
## 8) التحديث بعد كده (بدون أوامر Terminal)

أي تعديل تعمله في ملفات المشروع على جهازك:
1. افتح برنامج **GitHub Desktop**
2. هيلاحظ التعديلات لوحده ويظهرها في القائمة الشمال
3. اكتب وصف بسيط في خانة **Summary** (مثلاً: "تعديل صفحة المنتجات")
4. اضغط **Commit to main**
5. اضغط **Push origin** (الزرار فوق)

**Render** و **Cloudflare Pages** هيعملوا **إعادة نشر تلقائي** لوحدهم في خلال دقايق، من غير ما تعمل أي حاجة زيادة.

<a name="9"></a>
## 9) حل المشاكل الشائعة

| المشكلة | السبب المحتمل | الحل |
|---|---|---|
| صفحة `/api/docs` مش بتفتح | الباك إند لسه بيعمل Build، أو فشل | روح Render → Logs وشوف آخر رسالة خطأ، ابعتهالي |
| الواجهة بتفتح بس تسجيل الدخول بيفشل دايمًا | `VITE_API_URL` غلط أو ناقص `/api/v1` | راجعه في Cloudflare → Settings → Environment variables |
| ظاهر خطأ "CORS" في الـ Console (F12) | `FRONTEND_URL` في Render مش مطابق لرابط Cloudflare بالظبط | تأكد مفيش `/` زيادة في الآخر، والبروتوكول `https://` موجود |
| أول فتح للموقع بياخد 20-30 ثانية | طبيعي، الخطة المجانية في Render "بتنام" بعد 15 دقيقة خمول | استنى، المرة الجاية هيكون أسرع |
| الصفحة بتديلك 404 لو عملت Refresh على `/pos` مثلاً | ملف التوجيه ناقص | تأكد من وجود `apps/web/public/_redirects` في الكود المرفوع |
| فشل الـ Build في Render برسالة عن قاعدة البيانات | رابط Supabase غلط أو مستخدم Transaction pooler بدل Session pooler | ارجع لخطوة 2.3 وتأكد إنك ناسخ رابط **Session pooler** بالظبط |
| نسيت الـ Tenant ID | - | سجّل دخول كمدير عام على `/admin/login` وشوف قايمة التجّار |
| عايز تغيّر باسورد المدير العام | - | في Render أضف متغير مؤقت `MASTER_ADMIN_RESET_PASSWORD=true` بعد تغيير `MASTER_ADMIN_PASSWORD`، اعمل Redeploy، وبعدها احذف المتغير المؤقت |

## لو واجهتك مشكلة مش موجودة هنا

انسخ **نص رسالة الخطأ بالظبط** (من Render Logs أو من الـ Console في المتصفح بالضغط على F12) وابعتهالي، وهحدد السبب والحل فورًا.
