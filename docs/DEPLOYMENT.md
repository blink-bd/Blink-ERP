# دليل نشر المشروع على الإنترنت (بدون Web) — خطوة بخطوة

هذا الدليل يشرح إزاي تاخد المشروع وترفعه Web App حقيقي على الإنترنت، يقدر أي حد يفتحه من المتصفح بلينك، من غير ما يحمّل حاجة على جهازه.

**هنستخدم GitHub وRender Free وPostgreSQL مُدارة خارج Render وVercel. راجع حدود الخطة المجانية لدى كل مزود؛ لا تُخزّن قاعدة البيانات أو النسخ الاحتياطية على قرص Render المؤقت.**

| الخدمة               | الاستخدام                                               | الرابط                 |
| -------------------- | ------------------------------------------------------- | ---------------------- |
| **GitHub**           | تخزين الكود                                             | github.com             |
| **Render**           | تشغيل الباك إند (API) على Free                          | render.com             |
| **PostgreSQL خارجي** | قاعدة بيانات مُدارة عبر `DATABASE_URL` (مثلاً Supabase) | مزود PostgreSQL تختاره |
| **Vercel**           | تشغيل الواجهة (اللي بتفتحها في المتصفح)                 | vercel.com             |

> ⚠️ **Google Apps Script لا يصلح لهذا المشروع إطلاقًا** — هو مخصص لأتمتة Google Sheets/Gmail، مش لتشغيل تطبيقات NestJS + PostgreSQL. متحاولش تستخدمه هنا.

---

## الخطوة 1: إنشاء حساب GitHub ورفع الكود

### 1.1 أنشئ حساب

روح على github.com واعمل حساب جديد (لو مش عندك).

### 1.2 أنشئ Repository جديد

1. اضغط على الزر الأخضر **"New"** أو **"+"** فوق يمين الصفحة → **New repository**
2. اسم الـ Repository: `mobile-accessories-erp`
3. خليه **Private** (عشان الكود بتاعك)
4. متضغطش على "Add README" (عندنا واحد بالفعل)
5. اضغط **Create repository**

### 1.3 ارفع الكود من جهازك

افتح Terminal جوه مجلد المشروع (اللي فكيت ضغطه) واكتب:

```bash
cd mobile-accessories-erp
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/USERNAME/mobile-accessories-erp.git
git push -u origin main
```

غيّر `USERNAME` باسم حسابك على GitHub. هيطلبلك تسجل دخول (يمكن تستخدم Personal Access Token بدل الباسورد — GitHub هيوريك ده أول مرة).

بعد كده الكود هيبقى موجود على GitHub، وأي تعديل تعمله تقدر ترفعه بـ:

```bash
git add .
git commit -m "وصف التعديل"
git push
```

## الخطوة 2: إعداد PostgreSQL خارجي ونشر الباك إند على Render

### 2.1 أنشئ حساب على Render

روح على render.com → Sign Up → سجّل دخول بحساب الـ GitHub بتاعك مباشرة (أسهل حاجة).

### 2.2 اربط الـ Repository

1. أنشئ قاعدة PostgreSQL عند مزود خارجي (مثلاً Supabase) وخذ `DATABASE_URL` المناسب لاتصالات التطبيق.
2. من لوحة تحكم Render اضغط **New +** → **Blueprint**، واختر Repository المشروع.
3. ملف `render.yaml` ينشئ خدمة **`erp-api` فقط** على الخطة المجانية؛ قاعدة البيانات ليست على Render. أدخل `DATABASE_URL` ورابط الواجهة `FRONTEND_URL` عند إعداد المتغيرات.
4. أكمل الأسرار المطلوبة في Render Dashboard واضغط **Apply**.

### 2.3 استنى الـ Build يخلص

هياخد 5-10 دقايق أول مرة (بيثبت الحزم، يعمل build، يشغّل الـ migrations والـ seed تلقائيًا).

### 2.4 خد رابط الـ API

بعد ما يخلص، هتلاقي في صفحة `erp-api` رابط زي:

```
https://erp-api-xxxx.onrender.com
```

**احتفظ بالرابط ده** — هتحتاجه في الخطوة الجاية.

> ملحوظة: الخطة المجانية في Render بتـ"ينام" الخدمة لو محدش استخدمها 15 دقيقة، وبتاخد شوية ثواني تصحى تاني أول طلب. عادي تمامًا للتجربة.

## الخطوة 3: نشر الواجهة (الموقع اللي هتفتحه) على Vercel

### 3.1 أنشئ حساب على Vercel

روح على vercel.com → Sign Up → سجّل دخول بحساب الـ GitHub بتاعك.

### 3.2 استورد المشروع

1. اضغط **Add New** → **Project**
2. اختار الـ Repository `mobile-accessories-erp`
3. في خانة **Root Directory** اضغط **Edit** واختار `apps/web`
4. في **Environment Variables** ضيف:
   - Name: `VITE_API_URL`
   - Value: `https://erp-api-xxxx.onrender.com/api/v1` (رابط Render اللي خدته + `/api/v1` في الآخر)
5. اضغط **Deploy**

### 3.3 خد رابط الموقع

بعد ما يخلص (دقيقة أو دقيقتين)، Vercel هيديك رابط زي:

```
https://mobile-accessories-erp.vercel.app
```

ده رابط الواجهة.

> يعتمد تسجيل الدخول الآن على HttpOnly Cookies. ربط `*.vercel.app` مباشرةً بـ `*.onrender.com` قد يتأثر بحظر Cookies الطرف الثالث في بعض المتصفحات. للإنتاج الموثوق، استخدم نطاقاً مخصصاً مع Proxy من نفس الأصل أو نطاقين فرعيين تحت النطاق نفسه، واضبط `FRONTEND_URL` و`PUBLIC_APP_URL` على أصل الواجهة.

---

## الخطوة 4: اربط الرابطين ببعض (مهم جدًا)

عشان الباك إند يسمح للواجهة إنها تكلمه (CORS)، لازم ترجع لـ Render وتعدّل متغير `FRONTEND_URL`:

1. افتح خدمة `erp-api` في Render → **Environment**.
2. اضبط `FRONTEND_URL` على أصل الواجهة دون `/` أخيرة، و`PUBLIC_APP_URL` على الرابط نفسه لبناء رابط الإيصال.
3. أضف أي أصل إضافي موثوق في `CORS_ORIGINS` فقط عند الحاجة.
4. تحفظ Render التغييرات وتعيد تشغيل الخدمة. Cookies الإنتاج مضبوطة `Secure` و`SameSite=None`؛ النطاق المخصص نفسه هو الخيار الأفضل لتفادي قيود Cookies الطرف الثالث.

---

## الخطوة 5: إنشاء أول تاجر (Tenant)

نفس فكرة التشغيل المحلي، لكن دلوقتي هتستخدم رابط Render بدل localhost:

1. روح على `https://erp-api-xxxx.onrender.com/api/docs` (رابط الـ Swagger بتاعك)
2. استخدم `POST /api/v1/admin/tenants` بنفس الطريقة اللي شرحناها قبل كده
3. انسخ الـ `tenant.id` اللي هيرجعلك

---

## الخطوة 6: افتح النظام وسجّل دخول

روح على رابط Vercel بتاعك (`https://mobile-accessories-erp.vercel.app`)، وسجّل دخول بنفس الـ Tenant ID + الإيميل + الباسورد اللي عملتهم.

🎉 خلاص، النظام دلوقتي شغّال أونلاين وأي حد معاه الرابط يقدر يستخدمه.

---

## لو عايز تحدّث الكود بعد كده

كل مرة تعدّل حاجة في الكود وترفعها على GitHub (`git push`)، الاتنين Render وVercel هيعملوا **إعادة نشر تلقائي** لوحدهم من غير ما تعمل أي حاجة زيادة.

## أشهر المشاكل

| المشكلة                                              | الحل                                                                             |
| ---------------------------------------------------- | -------------------------------------------------------------------------------- |
| الواجهة بتفتح بس مش بتقدر تسجل دخول                  | تأكد إن `VITE_API_URL` في Vercel فيه `/api/v1` في الآخر                          |
| ظاهر خطأ CORS في الـ Console                         | تأكد إن `FRONTEND_URL` في Render مطابق تمامًا لرابط Vercel (من غير `/` في الآخر) |
| أول فتح للموقع بياخد وقت طويل                        | طبيعي في الخطة المجانية، الباك إند "بيصحى" من النوم                              |
| الصفحة بتدّيلك 404 لما تعمل refresh على `/pos` مثلاً | تأكد إن ملف `vercel.json` موجود في `apps/web` (موجود بالفعل في المشروع)          |

## الخطوة التالية (اختياري): دومين خاص بيك

كل من Render وVercel بيسمحولك تربطوا دومين خاص بيك (زي `erp.yourbusiness.com`) مجانًا من إعدادات المشروع → Domains.
